# 工具箱三类自定义工具设计

适用版本：`0.1.0`

## 1. 目标与范围

工具箱在 VS Code 底部 Panel 中以三行提供固定类别，用户可在面板内维护列表并点击条目直接执行：

1. **终端文件**：在资源管理器中右键本地工作区文件并添加到运行项，在集成终端运行，不限制扩展名。
2. **VS Code 命令**：执行 VS Code 或已安装扩展注册的命令 ID。
3. **Copilot 消息**：将保存的消息填入 Copilot Chat 输入框，由用户检查后自行发送。

状态栏工具箱图标用于切换底部 Panel 的显示与隐藏。面板 Webview 负责条目列表、表单、编辑、删除、输入校验、删除确认和状态反馈；运行文件通过 VS Code 资源管理器右键菜单添加。除资源管理器上下文菜单外，不使用 `showInputBox`、`showQuickPick`、`showOpenDialog`、原生确认框或原生消息框。扩展宿主负责存储、文件校验与实际执行，Webview 不直接访问文件系统、VS Code 命令或聊天内部状态。

不支持任意 Shell 命令文本、命令参数、运行历史、跨类别拖动、跨工作区同步或导入导出。终端文件通过资源管理器文件右键菜单添加，不按扩展名限制；胶囊可在同类别行内拖动排序，顺序会持久保存。

## 2. 面板交互

### 2.1 三类列表

面板按“运行”“消息”“命令”的固定顺序显示三行，每类胶囊自适应换行，最多显示两行；更多条目暂时裁切隐藏。运行项通过资源管理器右键菜单添加；消息和命令行的名称本身是新增按钮，加号在文字前，三行文字左对齐。新条目默认追加至类别末尾。

每个胶囊包含主要执行按钮（名称及目标摘要）和编辑、删除操作。点击名称立即执行；编辑和删除按钮不触发运行。胶囊可在同类别行内拖动调整顺序；聚焦名称按钮后也可用 `Alt+←/→` 移动，放开或保存后重载仍保持顺序。删除在 Webview 自有的确认层内二次确认。

状态消息显示在三行下方，左侧带绿色消息图标。成功、错误和普通提示统一使用绿色，并显示 3 秒倒计时后自动消失；新消息会重新开始倒计时。

### 2.2 Webview 表单

命令和消息使用面板内表单新增；所有类别均在面板内编辑，不离开工具箱。表单字段随类别变化：

- **终端文件**：从工作区资源管理器右键文件并选择“添加到工具箱运行项”后直接创建，名称默认使用文件名。编辑时可修改名称，文件路径保持不变。
- **VS Code 命令**：名称、命令 ID。可从宿主提供的已注册命令建议中选择，也可输入尚未注册的命令 ID，保存时不校验是否已注册。
- **Copilot 消息**：名称、消息正文。正文按普通文本保存，不解释为命令或模板；较长正文可在固定高度的文本框内滚动查看和编辑。

所有表单字段在提交时校验；名称去除首尾空白、不能为空，同一类别内忽略大小写后不得重名。表单标题在顶部行左侧，“取消”“保存”按钮在同一行右侧，按钮顶端与标题文字顶端对齐，字段在其下方单行排列。取消编辑不改变已有条目；保存成功后关闭表单并刷新当前类别。所有操作结果和错误在面板内状态区域反馈。

## 3. 数据模型与存储

使用 `context.workspaceState`，使配置按工作区隔离，并避免文件路径在其他仓库中误指向同名文件。当前版本化存储键为 `oneTap.shortcuts.v1`，保存各类条目及各自顺序：

```ts
type ShortcutItem = TerminalFileItem | VsCodeCommandItem | CopilotMessageItem;

interface TerminalFileItem {
  id: string;
  name: string;
  type: 'terminalFile';
  workspaceFolderUri: string;
  relativePath: string;
}

interface VsCodeCommandItem {
  id: string;
  name: string;
  type: 'vscodeCommand';
  commandId: string;
}

interface CopilotMessageItem {
  id: string;
  name: string;
  type: 'copilotMessage';
  message: string;
}
```

`id` 在创建时生成，编辑时保持不变。读取时验证版本、字段和类型；损坏数据不得静默覆盖，应在 Webview 中提示并保留原值。无工作区窗口可显示工具箱和命令/消息列表，但不能新建或运行工作区文件项，应在面板内说明需要打开本地工作区。

## 4. 执行行为

### 4.1 终端文件

- 仅接受本地 `file:` 工作区中的文件，不限制扩展名；远程或虚拟文件系统中的文件不支持执行。文件夹不能作为运行目标。
- 文件只能通过资源管理器右键菜单添加，资源管理器中多选的文件会一并添加；同一工作区中的同一文件不能重复添加，重复时在面板内提示已有运行项名称。宿主在添加和执行前验证目标确属当前本地工作区，并重新检查文件存在和真实路径边界；编辑运行项时目标取自已保存数据，不采用页面回传的路径。
- 多根工作区必须显式保存所属根目录 URI。路径包含关系按路径段校验，不能只比较字符串前缀。
- 由扩展宿主创建或复用本扩展持有的专用 PowerShell 终端，每次运行前先切换到所属工作区根目录，再安全引用文件路径后调用；路径中的 ASCII 单引号和 PowerShell 视为单引号的弯引号（U+2018、U+2019、U+201A、U+201B）均须重复转义。Webview 不得提交任意终端命令文本。
- 不按扩展名预先拒绝文件；终端负责执行并展示输出。打开终端并发送文件路径不代表目标成功执行，面板只反馈已发起或无法发起。

### 4.2 VS Code 命令

- 保存命令 ID，不保存本地化命令面板标题。执行时由宿主调用 `vscode.commands.executeCommand(commandId)`。
- 保存前在 Webview 中检查非空，并基于 `vscode.commands.getCommands()` 提供输入建议；不校验命令是否已注册，以兼容尚未激活的扩展命令。
- 点击条目后直接执行。命令不存在或执行抛错时，在面板显示命令 ID 和可读错误，不让异常逸出扩展宿主。
- 首版不传入命令参数；危险或具有破坏性副作用的命令仍由 VS Code/目标扩展自身负责确认，工具箱不绕过其保护流程。

### 4.3 Copilot 消息

- 每项保存名称和完整消息正文。点击条目后打开 Copilot Chat，并将正文追加到输入框已有内容之后；不提交、不触发发送，由用户检查或编辑后自行发送。
- 不带 `query` 执行 `workbench.action.chat.open` 聚焦输入框，再执行 `cursorBottom` 移到末尾，经剪贴板和 `editor.action.clipboardPasteAction` 粘贴“正文 + 换行”，最后恢复原剪贴板。带 `query` 打开会覆盖已有内容，因此不使用。
- `workbench.action.chat.open` 是 VS Code Workbench 内部命令，不属于有稳定兼容性承诺的扩展 API。用户已明确接受这一兼容风险；若命令在目标版本不可用或行为变化，面板须给出错误，不调用 DOM、注入脚本或自动发送作为回退。
- 聊天打开或预填失败时保留原列表和正文，在工具箱面板中给出可读错误。消息正文作为普通文本传递，不拼接为终端命令或 VS Code 命令参数。

## 5. Webview 与宿主边界

Webview 消息采用固定动作白名单，例如 `ready`、`reorder`、`save`、`delete`、`run`、`getItem`。资源管理器右键命令接收 VS Code 提供的资源 URI；运行请求只携带条目 ID，排序请求只携带类别及完整 ID 顺序。执行目标必须由宿主从存储中读取，不能信任页面回传的命令 ID 或文件路径。宿主校验消息形状、条目类型、顺序、路径和存储数据后再执行，并将结果通过受限响应消息返回页面。

页面继续使用扩展本地资源、严格 CSP 和 DOM 安全写入方式。用户提供的名称、路径摘要和消息正文均作为文本渲染，不作为 HTML 插入。所有错误提示、状态信息和确认交互都由 Webview 实现。

职责保持清晰：扩展入口负责注册状态栏面板切换、资源管理器文件添加命令、Panel 和生命周期；存储模块负责三类条目读写与排序；Webview 提供器负责页面资源、消息校验与数据推送；执行模块按类型运行终端文件、VS Code 命令或 Copilot 消息；工作区文件模块负责路径边界和真实路径校验，供添加与执行共用；纯数据校验可独立测试。移除原生 Quick Pick/InputBox 管理流程，不保留并行管理路径。

## 6. 错误与安全要求

- 用户取消表单或确认删除时不写入部分数据；删除必须经 Webview 内二次确认。
- 文件不存在、工作区失效、路径越界、终端不可用、命令未注册或执行失败时，在面板提供明确反馈；不因文件扩展名拒绝运行项。
- 终端路径在保存和执行阶段都校验；路径解析须覆盖符号链接，防止脚本真实位置越出工作区。
- 不接受任意 Shell 字符串。终端文件仅来自资源管理器右键添加，并始终经过 PowerShell 路径引用。
- Copilot 消息功能不得使用非公开内部接口；最低支持版本验证不通过时，不以不稳定的私有接口补齐行为。

## 7. 验收标准

1. 状态栏工具箱图标可打开或隐藏底部 Panel；运行、消息、命令三行按固定顺序显示。
2. 三类工具均可管理；运行项通过资源管理器右键菜单添加，消息和命令可在 Webview 新增，所有类别均可编辑、删除。
3. 每个条目点击主按钮即可触发对应行为；编辑、删除不会误触发运行；删除取消后数据保持不变。
4. 终端文件支持单根和多根本地工作区，路径含空格或单引号时正确运行；失效或越界路径被阻止。
5. VS Code 命令以命令 ID 执行；命令执行异常在面板内反馈。
6. Copilot 消息追加到聊天输入框末尾，不覆盖已有内容；点击工具不得自动提交，只有用户主动操作才会发送消息；内部命令兼容风险已向用户说明。
7. 重载后数据和类别内排序保留；损坏数据不会被静默覆盖。
8. 所有状态消息在列表下方以绿色显示，并有 3 秒倒计时和消息图标；新消息会重置倒计时。
9. Webview 不能指定绕过存储的执行目标；页面输入按文本安全渲染，不引入第三方依赖。
10. 扩展编译与相关自动化测试通过，覆盖三类模型校验、存储读写、排序、消息校验和执行分派。

## 8. 当前入口

1. 状态栏图标按工具箱视图可见状态打开或关闭底部 Panel。
2. 资源管理器文件右键命令创建本地工作区运行项。
3. Webview 负责三类工具的列表、同类别拖动排序、表单、删除确认及状态反馈。
4. 扩展宿主负责工作区校验、工作区状态存储和文件、命令、Copilot 消息的执行。
