# 开发者工具箱三类自定义工具设计

## 1. 目标与范围

开发者工具箱在 VS Code 底部 Panel 中提供三个固定类别，用户可在面板内维护列表并点击条目直接执行：

1. **终端文件**：在集成终端运行本地工作区中的 PowerShell 脚本。
2. **VS Code 命令**：执行 VS Code 或已安装扩展注册的命令 ID。
3. **Copilot 消息**：将保存的消息填入 Copilot Chat 输入框，由用户检查后自行发送。

面板 Webview 是唯一的管理与操作界面。新增、编辑、删除、输入校验、删除确认和错误反馈均在 Webview 中完成；不得使用 `showInputBox`、`showQuickPick`、`showOpenDialog`、原生确认框或原生消息框。扩展宿主负责存储、工作区文件枚举与实际执行，Webview 不直接访问文件系统、VS Code 命令或聊天内部状态。

首版不支持任意 Shell 命令文本、命令参数、运行历史、拖拽排序、跨工作区同步或导入导出。终端文件沿用现有 `.ps1` 支持范围；其他文件类型需要明确运行器和参数规则后再扩展。

## 2. 面板交互

### 2.1 三类列表

面板顶部提供“终端文件”“VS Code 命令”“Copilot 消息”三个页签，并分别显示条目数量。每个页签显示自己的条目列表和空状态；空状态提供该类别的新增按钮。条目按创建顺序排列。

每行包含主要执行按钮（名称及目标摘要）和编辑、删除操作。点击主要区域立即执行，不额外弹出管理菜单。删除在 Webview 自有的确认层内二次确认。顶部新增按钮跟随当前类别，用户可从当前页直接创建该类条目。

### 2.2 Webview 表单

新增和编辑使用面板内表单/对话层，不离开工具箱。表单字段随类别变化：

- **终端文件**：名称、工作区根目录、工作区相对文件路径。通过 Webview 内的可搜索文件浏览器选择 `.ps1` 文件；多根工作区明确显示根目录，不调用系统文件选择器。
- **VS Code 命令**：名称、命令 ID。可从宿主提供的已注册命令建议中选择，也可输入命令 ID；未注册时在表单内提示，用户仍可选择保存。
- **Copilot 消息**：名称、消息正文。正文按普通文本保存，不解释为命令或模板。

所有表单字段在提交时校验；名称去除首尾空白、不能为空，同一类别内忽略大小写后不得重名。取消编辑不改变已有条目；保存成功后关闭表单并刷新当前类别。所有操作结果和错误在面板内状态区域反馈。

## 3. 数据模型与存储

沿用 `context.workspaceState`，使配置按工作区隔离，并避免脚本路径在其他仓库中误指向同名文件。建议使用版本化存储键 `vscodeTools.tools.v2`，保存各类条目及各自顺序：

```ts
type ToolItem = TerminalFileItem | VsCodeCommandItem | CopilotMessageItem;

interface TerminalFileItem {
  id: string;
  name: string;
  type: 'terminalFile';
  workspaceFolderUri: string;
  relativePath: string;
}

interface VsCodeCommandItem {
  id: string;
  name: string;
  type: 'vscodeCommand';
  commandId: string;
}

interface CopilotMessageItem {
  id: string;
  name: string;
  type: 'copilotMessage';
  message: string;
}
```

`id` 在创建时生成，编辑时保持不变。读取时验证版本、字段和类型；损坏数据不得静默覆盖，应在 Webview 中提示并保留原值。升级时将现有脚本项和命令项转换为对应的新类型，保留 ID、名称、目标和相对顺序；迁移成功后只读写新格式，不保留旧管理流程。无工作区窗口可显示工具箱和命令/消息列表，但不能新建或运行工作区文件项，应在面板内说明需要打开本地工作区。

## 4. 执行行为

### 4.1 终端文件

- 仅接受本地 `file:` 工作区中的 `.ps1` 文件；远程或虚拟文件系统中的文件不支持执行。
- Webview 内文件浏览器按需读取工作区目录，只展示文件路径和目录；宿主保存时验证目标确属选择的工作区，且执行前重新检查文件存在、扩展名和真实路径边界。
- 多根工作区必须显式保存所属根目录 URI。路径包含关系按路径段校验，不能只比较字符串前缀。
- 由扩展宿主创建或复用本扩展持有的专用 PowerShell 终端，使用正确的 PowerShell 单引号转义发送脚本路径。Webview 不得提交任意终端命令文本。
- 打开终端并发送脚本不代表脚本成功结束；终端负责展示运行输出，面板只反馈已发起或无法发起，不伪报执行成功。

### 4.2 VS Code 命令

- 保存命令 ID，不保存本地化命令面板标题。执行时由宿主调用 `vscode.commands.executeCommand(commandId)`。
- 保存前在 Webview 中检查非空，并可基于 `vscode.commands.getCommands()` 提示命令当前未注册；允许用户确认后保存，以兼容尚未激活的扩展命令。
- 点击条目后直接执行。命令不存在或执行抛错时，在面板显示命令 ID 和可读错误，不让异常逸出扩展宿主。
- 首版不传入命令参数；危险或具有破坏性副作用的命令仍由 VS Code/目标扩展自身负责确认，工具箱不绕过其保护流程。

### 4.3 Copilot 消息

- 每项保存名称和完整消息正文。点击条目后打开 Copilot Chat，并将正文填入输入框；不提交、不触发发送，由用户检查或编辑后自行发送。
- 仅使用当前目标 VS Code 版本中可验证、受支持的调用方式；不得依赖 Copilot Chat 未公开的内部命令、DOM 操作或 Webview 注入。
- 实现前需在声明支持的最低 VS Code 版本（当前 `engines.vscode` 为 `^1.90.0`）验证受支持的调用方式能否打开 Copilot Chat 并预填文本。不得依赖未公开的内部命令、DOM 操作或 Webview 注入；若公开能力无法预填，则在面板内说明不受支持，并重新确认可行方案。
- 聊天打开或预填失败时保留原列表和正文，在工具箱面板中给出可读错误。消息正文作为普通文本传递，不拼接为终端命令或 VS Code 命令参数。

## 5. Webview 与宿主边界

Webview 消息采用固定动作白名单，例如 `ready`、`listFiles`、`create`、`update`、`delete`、`run`。消息只携带类别、条目 ID 和经表单提交的字段；运行请求只携带条目 ID，执行目标必须由宿主从存储中读取，不能信任页面回传的命令 ID 或文件路径。宿主校验消息形状、条目类型、路径和存储数据后再执行，并将结果通过受限响应消息返回页面。

页面继续使用扩展本地资源、严格 CSP 和 DOM 安全写入方式。用户提供的名称、路径摘要和消息正文均作为文本渲染，不作为 HTML 插入。所有错误提示、状态信息和确认交互都由 Webview 实现。

职责保持清晰：扩展入口负责注册 Panel 和生命周期；存储模块负责三类条目读写及版本迁移；Webview 提供器负责页面资源、消息校验与数据推送；执行模块按类型运行终端文件、VS Code 命令或 Copilot 消息；纯数据校验可独立测试。移除旧状态栏入口和原生 Quick Pick/InputBox 管理流程，不保留并行管理路径。

## 6. 错误与安全要求

- 用户取消表单或确认删除时不写入部分数据；删除必须经 Webview 内二次确认。
- 文件不存在、工作区失效、路径越界、文件类型不支持、终端不可用、命令未注册或执行失败时，在面板提供明确反馈。
- 终端路径在保存和执行阶段都校验；路径解析须覆盖符号链接，防止脚本真实位置越出工作区。
- 不接受任意 Shell 字符串。终端脚本来自受限工作区文件选择，并始终经过 PowerShell 参数转义。
- Copilot 消息功能不得使用非公开内部接口；最低支持版本验证不通过时，不以不稳定的私有接口补齐行为。

## 7. 验收标准

1. 工具箱入口位于 VS Code 底部 Panel；三个页签及各自数量、空状态和列表均可用。
2. 三类工具均可在 Webview 内新增、编辑、删除；没有 VS Code 原生输入框、选择器、确认框或消息框参与管理。
3. 每个条目点击主按钮即可触发对应行为；编辑、删除不会误触发运行；删除取消后数据保持不变。
4. 终端文件支持单根和多根本地工作区，路径含空格或单引号时正确运行；失效或越界路径被阻止。
5. VS Code 命令以命令 ID 执行；未注册命令和执行异常均在面板内反馈。
6. Copilot 消息在最低支持 VS Code 版本上通过受支持接口打开并预填；点击工具不得自动提交，只有用户主动操作才会发送消息。
7. 重载后数据保留；现有脚本和命令项迁移后内容及顺序正确；损坏数据不会被静默覆盖。
8. Webview 不能指定绕过存储的执行目标；页面输入按文本安全渲染，不引入第三方依赖。
9. 扩展编译与相关自动化测试通过，覆盖三类模型校验、存储迁移、消息校验和执行分派。

## 8. 实施顺序

1. 验证 VS Code 最低支持版本是否具备受支持的 Copilot Chat 打开与预填能力；不满足时先调整设计或最低版本，不使用私有接口。
2. 定义三类数据模型、v2 存储格式、旧条目迁移和 Webview 消息协议。
3. 在 Panel Webview 实现三页签、列表、表单、文件浏览器、删除确认及面板内状态反馈。
4. 在宿主实现严格消息校验和三类执行器，删除旧状态栏及原生管理逻辑。
5. 增加针对模型/存储/协议/执行分派的测试，并按验收标准验证工作区边界、聊天预填行为和“不自动发送”约束。
